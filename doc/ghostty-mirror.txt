1. INTRODUCTION                                   *ghostty-mirror-introduction*

ghostty-mirror mirrors Neovim's active colorscheme into Ghostty, and
optionally tmux. On `:colorscheme`, it points Ghostty's config-file include at
a matching theme and signals a reload, so the terminal flips theme instantly
across every open window.

A theme is resolved by precedence: a hand-made or cached file at
`themes_dir/<name>` wins (honoring the light variant when 'background' is
"light"); otherwise one is generated from live highlights and cached. The
plugin owns only the include file and the themes it generates — never your
main Ghostty config or hand-made theme files.

Requires Neovim 0.10+.

Setup is automatic with defaults; call |ghostty-mirror.setup()| to override.
>lua
    require("ghostty-mirror").setup({})
<
==============================================================================
2. COMMANDS                                           *ghostty-mirror-commands*

                                                              *:ThemeFromGhostty*
:ThemeFromGhostty   Apply the colorscheme named in Ghostty's theme file to this
                    Neovim instance. Run it in other nvim windows to re-sync
                    them without restarting.

                                                                *:ThemeToGhostty*
:ThemeToGhostty     Force-regenerate the current colorscheme's Ghostty theme
                    from live highlights, overwriting any cached/hand-made
                    file. Useful after tweaking a colorscheme's options.

                                                                  *:ThemeToTmux*
:ThemeToTmux        The tmux analog of |:ThemeToGhostty| (when tmux mirroring
                    is enabled).

                                                              *:ThemeCacheClear*
:ThemeCacheClear    Delete every generated theme file (recognized by their
                    header); hand-made files are left untouched. The next
                    `:colorscheme` regenerates fresh.

3. CONFIGURATION                                 *ghostty-mirror-configuration*

                                                        *ghostty-mirror.setup()*
require("ghostty-mirror").setup({opts})

Fields of {opts} (showing defaults):

themes_dir            string   ~/.config/ghostty/themes
                      Directory Ghostty reads themes from.

theme_file            string   ~/.config/ghostty/theme-current
                      Include file the plugin writes `theme = <name>` to.

light_variant_suffix  string   "-light"
                      Suffix for light-mode variant files. "" or false
                      disables variant routing.

generate              boolean  true
                      Generate a theme from live highlights when no file
                      exists. false requires hand-made files.

reload_command        string[] { "pkill", "-SIGUSR2", "ghostty" }
                      Command used to tell Ghostty to reload its config.

debounce_ms           integer  150
                      Coalesce rapid `:colorscheme` changes (a picker's live
                      preview) and mirror once the scheme settles. 0 mirrors
                      synchronously on every change.

overrides             table    {}                    *ghostty-mirror-overrides*
                      Per-theme tweaks merged into Ghostty theme generation,
                      keyed by the resolved theme name (a light variant keys
                      separately, e.g. "ron-light"). Recognized params:
                      background, foreground, cursor_color, cursor_text,
                      selection_background, selection_foreground (colors,
                      "#rgb" or "#rrggbb"; underscores map to Ghostty's
                      dashed directives) and palette, a table of individual
                      ANSI slots keyed 0..15. A color param replaces its
                      highlight-derived value and is emitted even when the
                      highlight lacks one; palette slots substitute into the
                      scheme's own palette, or are emitted as a partial
                      palette when the scheme owns none. Edits apply on the
                      next |:colorscheme| or restart: the cached file
                      regenerates and Ghostty reloads. setup() warns about an
                      override that cannot take effect (unknown theme,
                      unknown param, invalid value or palette slot); a bad
                      value falls back to the highlight-derived color.
                      Overrides never touch hand-made theme files. Example: >lua
                          overrides = { ron = { background = "#101010" } }
<

manage_background     boolean  false
                      Opt-in. Keep 'background' honest across switches:
                      baseline to dark before a scheme loads (so adaptive
                      schemes like `default` don't inherit a stale "light")
                      then sync it to the loaded scheme's Normal-bg luminance.
                      See |ghostty-mirror-troubleshooting|.

sync_on_startup       boolean  false
                      Opt-in. On VimEnter, apply the theme named in theme_file
                      so a freshly-opened nvim follows Ghostty's current theme.

sync_on_focus         boolean  false
                      Opt-in. On FocusGained, re-apply the theme_file theme
                      when it differs from the loaded one, so multiple nvim
                      instances re-sync to whichever last wrote it.

tmux                  table    { enabled = false, ... }
                      Opt-in tmux statusline mirroring. Fields: enabled,
                      themes_dir, theme_file, generate, reload_command,
                      bar_blend, accent_hl, divider_hl, overrides. See the
                      README.

tmux.overrides        table    {}               *ghostty-mirror-tmux-overrides*
                      Per-theme tweaks merged into tmux theme generation.
                      Same keying, validation and regeneration semantics as
                      |ghostty-mirror-overrides|. Recognized params: accent,
                      divider, bar (colors, "#rgb" or "#rrggbb") and
                      bar_blend (0..1). accent/divider/bar_blend replace
                      generation's inputs, so derived colors recompute
                      coherently; bar sets the status bar color directly,
                      bypassing the blend (and bar_blend). Example: >lua
                          tmux = { overrides = { ron = { accent = "#fff" } } }
<

==============================================================================
4. HEALTH                                               *ghostty-mirror-health*

Run >
    :checkhealth ghostty-mirror
<
to diagnose the common, environment-side failure modes: an un-writable
`themes_dir`/`theme_file`, a `reload_command` not on $PATH, no running Ghostty
process, and (when tmux mirroring is enabled) an un-writable tmux dir/file or
tmux missing from $PATH.

==============================================================================
5. TROUBLESHOOTING                             *ghostty-mirror-troubleshooting*

A "stuck" or desynced theme is almost always the environment, not the plugin
(which faithfully mirrors the last settled `:colorscheme`). Suspect, in order:

- A colorscheme picker spraying transient previews — the debounce
  (|ghostty-mirror-configuration| `debounce_ms`) is the fix; check it isn't 0.
- A config that reads theme_file at startup to pick the colorscheme — that is
  an input+output feedback loop.
- Multiple nvim instances sharing one theme_file — last writer wins by design;
  that is how |:ThemeFromGhostty| re-syncs windows.

A light scheme can leave 'background' stuck: some schemes (catppuccin-latte)
set `background=light` and never reset it, so an 'background'-adaptive scheme
loaded afterwards (the built-in `default`) renders its light variant, which
the plugin faithfully mirrors. Set `manage_background = true` to have the
plugin reset and re-sync 'background' for you.
